# 国际化（i18n）

界面支持 **简体中文 / 繁體中文 / English / 日本語**：首次启动按系统语言自动选择（其它语言回退英文），
设置页「外观 → 语言」可即时切换、**无需重启**，选择写入 `config.json` 的 `language` 字段
（`auto` / `zh-Hans` / `zh-Hant` / `en` / `ja`）。目录完整性由
[`tests/i18n_catalog.rs`](../crates/tianyi-app/tests/i18n_catalog.rs) 守护，改完文案先跑：

```pwsh
cargo test -p tianyi-app --offline --test i18n_catalog
```

## 1. 两套目录，各管一段

| 目录 | 管什么 | 谁读它 | 何时生效 |
| --- | --- | --- | --- |
| `lang/<lang>/LC_MESSAGES/tianyi-app.po` | `.slint` 里 `@tr("…")` 的界面文案 | Slint 运行时（gettext 语言包） | **编译期**由 `build.rs` 打包，运行时切包 |
| `i18n/rs/<lang>.json` | Rust 侧 `format!` 拼出来的文案（状态栏、提示条、任务状态、文件类型、剩余时间） | `src/i18n.rs` 的 `t()` / `tf()` | 首次查词时 `include_str!` + `serde_json` 解析，`OnceLock` 缓存 |

（上表路径相对 `crates/tianyi-app/`。）

**为什么不能统一**：`.slint` 的 `@tr` 由 `slint-build` 在**编译期**扫描，只认
`lang/<lang>/LC_MESSAGES/tianyi-app.po` 这个固定布局（`with_bundled_translations("lang")`），看不见
运行时的 JSON；反过来，控制器里的 `t("toast.copied")` 是普通 Rust 调用，**压根不经过 Slint 表达式
求值**，`@tr` 也管不着——两条管线的输入格式、加载时机、失效方式都不同，只能各留一套，靠测试同步。
`.slint` 侧不开 msgctxt（`with_default_translation_context(None)`）：全库共用一张 msgid 表，同一句
文案在 `main.slint` 与各组件里只算一条，翻译不用重复填。

## 2. 为什么 msgid / 键值都是简体中文

Slint 把 `@tr("原文")` 的原文放在翻译表的**索引 0**，也就是「没选中任何语言」时的回退项。源码文案
本来就是简中，于是「msgid = 简中原文」同时是三件事：① 界面代码里读到的是可直接审阅的中文，而不是
`settings.language.title` 这类键；② 简中不需要翻译文件——**索引 0 就是简中**；③ 漏翻时自动回落成
中文原文，界面永远不会出现空串或键名。Rust 侧刻意复用同一思路：`i18n/rs/zh-Hans.json` 是**唯一
完整**的词表（键 → 简中原文），其它语种只填翻好的项，查词顺序「当前语种 → 简中 → 键名」。

**因此 `lang/zh-Hans/` 目录不能存在**（D 组断言钉住）：多出这个目录会让「未选中任何语言」时的回退
语言被一份空 `.po` 顶掉，界面直接掉成空串。`Lang::code()` 对简中返回空串，正是「选索引 0」的写法。

## 3. 运行时切语链路

```
设置页「外观 → 语言」 → Controller::set_language_index(idx)
  ① 钳制 0..=4 并落盘 config.json（配置是唯一事实来源，重启后仍是它）
  ② 清掉旧语种的瞬时文案（提示条 / 状态栏 / 列表加载错误）
  ③ i18n::apply(Lang)  →  ④ slint::select_bundled_translation(Lang::code())
  ⑤   运行时把翻译标记为已脏，下一帧所有 @tr 绑定重算
  ⑥ 重推 Rust 侧拼出来的字符串（refresh_transfers 等）
  ⑦ 回填用户选的模式（Auto 回填 0，而非解析出的语种）+ 保存失败提示
```

`i18n::apply` 必须在**首个组件创建之后**调用（翻译包随组件注册进运行时，更早调用只会拿到
`NoTranslationsBundled`）；切失败只记 warn，不让界面起不来。

## 4. 「自动」模式的 locale 解析

`i18n::map_locale` 先把标签小写、再按 `-` / `_` 切子标签，**繁体优先**：

| 系统语言（BCP-47） | 结果 |
| --- | --- |
| `zh-Hant`、`zh-TW`、`zh-HK`、`zh-MO` | 繁體中文 |
| `zh-Hans`、`zh-CN`、`zh-SG`、`zh-MY`、裸 `zh`、其它 `zh-*` | 简体中文 |
| `ja`、`ja-JP` | 日本語 |
| `en-US`、`de-DE`、空串、取不到系统语言 | English（回退） |

Slint 自己的语言包匹配是**粗粒度的**（按目录名 / 主标签比对，不做 `zh-TW → zh-Hant` 这类区域推断），
所以区域与脚本的判定全部收在 `map_locale` 里，一处改、处处生效。

## 5. 新增一条文案

**两端各写一遍，缺一边都会静默回退成中文。** `.slint` 侧：① 直接写 `text: @tr("要显示的中文");`，
要插值就 `@tr("已选择 {0} 项", root.selected-count)`；② `pwsh tools/i18n-extract.ps1 -Count` 看
msgid 去重数的变化；③ 三份 `.po` 各补 `msgid "要显示的中文"` + `msgstr "…"`；④ 跑测试（A 组点出
缺哪条，B 组点出多哪条）。

Rust 侧：① `i18n/rs/zh-Hans.json` 先加键值对——它是完整的基准表；② 三个语种的 JSON 加同一条键，
**占位符必须一字不差**（`{name}` / `{count}` / `{e}` 都是具名占位符）；③ 代码里用 `t("toast.xxx")`
或 `tf("toast.xxx", &[("count", &n)])`；④ 跑测试（C 组点出键集差异、空值、占位符不一致）。
缺条目时可用骨架脚本补，⚠ 会覆盖同名文件，先另存已有译文：

```pwsh
pwsh tools/i18n-extract.ps1 -Skeleton ja   # 写 lang/ja/LC_MESSAGES/tianyi-app.po，msgstr 留空
```

## 6. 新增一门语言

1. 建 `lang/<code>/LC_MESSAGES/tianyi-app.po`，`<code>` 必须与 `Lang::code()` 返回值**字面一致**（Slint 按目录名查包）；
2. 建 `i18n/rs/<code>.json`，键集与 `zh-Hans.json` 相同；
3. `src/i18n.rs`：`Lang` 加枚举项，`index()` / `from_index()` / `code()` 各补一臂，再补 `table()` 的 `include_str!` 与 `OnceLock`；
4. `tianyi_core::config::LanguageMode` 加枚举项与 `as_str()` / `parse()`；
5. 设置页 `ui/pages/settings.slint` 的「外观 → 语言」加一段（索引 0=自动 1=简中 2=繁中 3=英文 4=日文），同步改 `set_language_index` 的 `clamp(0, 4)` 与 `language_mode_from_index`；
6. `tests/i18n_catalog.rs` 的 `PO_LANGS` / `JSON_LANGS` 加进新语种，再跑测试。

## 7. 已知限制（如实记录）

1. **底层错误文本仍是中文**：`{e}` 插进去的是 `tianyi_core::Error` 的 `Display` 输出，恒为中文，英文界面上会出现「Transfer failed: 网络请求超时」这类混排；要根治得给 core 的错误枚举做结构化翻译，本轮没做。
2. **日志不翻译**：`log::info!` / `log::warn!` 一律中文，只供开发者与排障使用。
3. **云端「新建文件夹」的默认目录名随界面语种变化**（`state.default_folder_name`）：英文界面下会创建名叫 `New folder` 的云端目录。这是**有意为之**——用户看到什么就建什么；代价是云端真实目录名与界面语言绑定，切语后新建的目录名会不同。
4. **测试 / 预览必须显式钉简中**：`examples/ui_preview.rs` 先 `slint::select_bundled_translation("")`（空串 = 索引 0 = 简中）再采图；不钉的话截图与文案断言会随开发机的系统 locale 漂移——Slint 的标签匹配是粗粒度的，不会替你纠正。

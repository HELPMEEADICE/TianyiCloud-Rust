## 3. 非 UI 改动（摘要）

**正确性**：请求级重试与指数退避（200/600/1800ms ±20%，只对幂等 GET 与 5xx/429 生效）；会话失效判定从字符串匹配改为结构化错误码；HTTP client 构建失败三级降级而非 panic；配置加载带版本号与迁移链；关窗时把未完成任务归一化为「已暂停」并落盘（选暂停而非取消，因为取消是终态、会丧失续传能力）。

**性能**：目录大小统计移出 UI 线程；UI 线程调用不再多排一次事件循环；传输列表改为快照比对增量推送（进度阈值 1%）；任务级并发上限 3（与分片级并发是两层控制）；`icon-sheet.slint`（5955 行）常规构建不再编译。

**架构**：`controller.rs` 4413 行拆为 5 个模块，函数名集合与测试集合完全一致，行为零变更。

**可访问性**：启用 `accessibility` feature（accesskit 传递依赖原本就在 lock 文件里，未新增依赖）；关键控件有 role/label；控件可聚焦、Space/Enter 激活、键盘模式显示焦点环。**Tab 遍历由 Slint 运行时提供**（`i-slint-core/src/window.rs:1122-1142` 在事件未被 accept 时调 `focus_next_item()`；`TouchArea` 的 `focus_event` 恒 `FocusIgnored`，不会成为多余停靠点），因此不需要自建有序焦点模型。

**测试**：新增 Slint 测试后端的几何断言（登录卡片居中、状态栏胶囊跨档宽度不变量、右键菜单四角钳制、空状态图标居中、三档窗口列头存在性、6 类控件的可访问角色与标签），以及 core 持久化公共 API 集成测试。

**工程**：`rust-toolchain.toml`；MSRV 由实测校准（1.75 → **1.92**，依据 slint 1.17.1 自身声明）；CI 增 Windows 测试、MSRV、`cargo-deny`、覆盖率（后两者 `continue-on-error` 且不进汇总门禁）；Windows 便携包；版本一致性校验脚本；日志同时落盘并按天滚动保留 7 天。

## 4. 验证方式（这是本轮真正的产出）

四道闸门（每个提交前）：`cargo fmt --check`、`cargo test --workspace`、`pwsh tools/clippy.ps1`（等价 `-D warnings`）、`cargo check --workspace --all-targets`。

三道**超出常规**的验证：

1. **变异测试**：把每个已修缺陷人为制造回去，确认断言真的变红。它揭穿了一条假绿——状态栏胶囊的原始断言"右边缘贴右 + 宽度 < 窗宽/2"永远不可能失败（最右子元素的右边缘天然等于容器右边缘，阈值 450 又比变异后的 426 还宽），已改为**跨档宽度不变量**（两档窗口宽度差 ≤1px，与字体度量无关）。
2. **隔离实验**：并行代理改动同一棵树时，把自己的文件临时回退再采样，把"我的改动"与"别人的改动"分离。结论 20/22 张基线图字节一致，剩余 2 张差异经同二进制连渲两次证明是 spinner 动画相位。
3. **真机运行时验证**：启动 12 秒无 panic；用 `WM_CLOSE` 触发 `close-requested`，确认关窗钩子执行、进程以退出码 0 优雅退出；确认日志真的写进 `%APPDATA%\tianyi-cloud-rust\logs\tianyi-cloud.<日期>.log` 且时间戳为本地时间。

## 5. 方案自我修正记录（保留，避免后人重犯）

1. **DE-09 剔除**：见 §2。方案里凭"620 高窗口"直觉判定为缺陷，实际算下来内容区仍有 360px。
2. **EN-04 剔除**：原计划把 200ms ticker 在空闲时降到 1s。EN-03 落地后空闲 tick 只剩一次原子交换，是噪声级开销；真正的开销（全量重建两个模型）已被增量刷新解决。不再为它改 `main.rs`。
3. **任务书三处规格错误，均由执行方查证 API 时发现**：
   - `TextInput::key-pressed` 的 accept/reject 语义写反（按字面实现会让重命名框**完全无法输入**，比原缺陷更严重）；
   - `crate::app::InputMode` 不存在——Slint 只为根文档**显式导出**的 global 生成 Rust 类型；
   - `accessible-label` 是保留属性、不可在组件里重声明（`is_shadowable: false`），标签必须在调用点设置。
4. **两处假绿**：上述胶囊断言；以及 CHANGELOG 里两条与代码不符的描述（`accounts.json` 并无 version 字段；HTTP client 是三级降级而不是"返回错误并向上传递"）。
5. **门禁命令 ≠ 自检命令**：`tools/clippy.ps1` 跑 `--all-targets`，能抓到普通 `cargo check` / `cargo test` 看不到的问题（本轮实抓到 test target 里的 doc comment 位置错误）。
6. **构建产物陈旧陷阱**：`build.rs` 只声明 `cargo:rerun-if-changed=ui`（目录级），Windows 下改目录内文件不改目录 mtime，生成码可能不刷新；`cargo test` 不刷新 bin、`cargo check` 不产出 bin。做真机验证前必须 `cargo build`，做视觉回归前必要时 `cargo clean -p tianyi-app`。

方法论结论：**任务书应规定"要达到的可观测结果"，而不是替执行者预设 API 细节**。三次规格错误全部出自后者。

## 6. 明确不做的项与理由

| 项 | 理由 |
| --- | --- |
| i18n 中英双语 | 需改 22 个 `.slint` 的每句文案，diff 巨大、回滚粒度是整个界面；当前文档/注释/目标用户均为中文，改动面与收益严重不成比例 |
| 文件缩略图 | 需要下载缓存 + 并发上限 + 失败降级三件套，否则反而拖慢列表；应单独一轮做，不适合塞进收尾批次 |
| 系统托盘 | 引入新的窗口生命周期语义（最小化到托盘、托盘退出），会与刚完成的"关窗落盘"互相干扰，需专门设计 |
| 列宽拖拽 | 纯增量交互，但会与 `detail-level` 三档断点机制耦合，改完需重新校准全部断点 |
| 全局速度限制 | `AppConfig.speed_limit` 已存在但实现需把令牌桶贯穿到分片级并发路径（core 层改动），风险高于本轮收尾能承担的范围 |
| 失败自动重试（任务级） | 与请求级重试语义不同，且需与任务状态机、并发信号量协调，应单独一轮设计与验证 |

## 7. 残余限制（诚实清单）

1. **键盘可达性覆盖不完整**：按钮/图标按钮/导航项/菜单项/复选/开关/分段控件已可聚焦并有焦点环；`FluentTextField`、文件列表行、传输行、对话框、搜索框**仍非键盘可达**。焦点环的实际观感、Tab 顺序是否符合直觉、中文 IME 下 Space/Return 行为，均需真机与屏幕阅读器验证。
2. **`FluentMenuItem` 用 `button` 角色**（Slint 无 menuitem 角色），屏幕阅读器会读成按钮而非菜单项。
3. **两处 Tooltip 归属键可能同类碰撞**：`"tip:" + tooltip` 在文案重复时不唯一（实测"关闭提示"出现 2 次），若两者同时可见并快速交替悬停仍会互相关灯。彻底修法需给 icon-button 实例级唯一键，会改动 15 处调用点。
4. **`tianyi-core` 的锁中毒未治理**：本轮只把 `tianyi-app` 侧 97 处 `.lock().unwrap()` 归零，core 侧未审计。
5. **配置降级与日志目录不同源**：主配置目录不可写时，配置会退到 `%TEMP%\tianyi-cloud-fallback`，而日志仍按主路径解析（写失败则退化为仅 stderr），设置页两行路径在这种场景下会不一致。
6. **关窗落盘存在毫秒级竞态**：`ctl.cancel()` 后在跑的任务可能在进程退出前几毫秒走到 `Canceled` 分支覆盖写回。彻底解法是加 `shutting_down` 标志，本轮刻意未动传输收尾路径。
7. **单日日志无大小上限**：只按天滚动 + 7 天保留。
8. **真实账号链路未回归**：本轮无可用账号，登录/列目录/上传下载的真实交互未验证；相关改动集中在 UI、状态编排与错误处理层。
9. **macOS 30 秒轮询分支在 Windows 上不参与编译**，未实测。
10. **首次 CI 运行预期**：`audit` 会因 slint 系 crate 的 `LicenseRef-*` 自定义许可而报"不在白名单"，这是刻意保留的事实暴露（作业 `continue-on-error`，不影响门禁）。
